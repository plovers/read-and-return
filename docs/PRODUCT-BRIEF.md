# Read and Return — 项目开发说明

## 1. 项目背景

Read and Return 是一个独立的 Obsidian 插件，主要解决**长笔记中的阅读位置导航问题**。

实际使用中，尤其是在 Obsidian 手机 App 上阅读较长的笔记时，经常会遇到这样的场景：

- 当前正在笔记中间某处阅读；
- 临时想回到笔记开头或前面的某一部分查看内容；
- 查看结束后，希望快速返回刚才的阅读位置；
- 目前只能不断上下滑动，并重新寻找原来的位置，长笔记中体验很差。

桌面端可以依赖滚动条、鼠标等方式快速移动，但在手机 App 中，这个问题尤其明显。

因此，本插件应当以：

> **Mobile First / 长笔记快速导航**

作为核心设计方向。

## 2. 主要使用场景

典型流程：

```
正在阅读长笔记中间位置
        ↓
想看看笔记最前面的内容
        ↓
一键跳到顶部
        ↓
查看完成
        ↓
一键返回刚才的位置
```

另外还包括：

```
位置 A
  ↓
跳到位置 B
  ↓
跳到位置 C
  ↓
后退到 B
  ↓
后退到 A
```

目标是让长笔记中的位置移动更接近浏览器的：

**Back / Forward**

而不是依赖反复手工滚动。

## 3. 第一阶段核心功能

第一版本优先实现少量但可靠的功能。

### 临时返回点

用户可以把当前阅读位置暂时记录下来，然后前往笔记中的其他位置。

之后通过一个简单操作直接返回原位置。

临时位置主要用于当前阅读过程，不要求永久保存。

### 跳到顶部并返回

这是最重要的快捷操作之一。

用户点击：

**↑ 顶部**

插件自动：

1. 记录当前位置；
2. 跳到当前笔记顶部。

此时用户可以直接执行：

**↩ 返回**

回到刚才的位置。

用户不应该需要先手动“创建书签”。

### 前进 / 后退导航

维护当前阅读过程中的位置历史：

```
← Back
→ Forward
```

体验类似浏览器或 IDE 的位置历史。

## 4. Mobile First

这个插件主要为 **Obsidian 手机 App** 使用，因此移动端不是桌面版的附带适配，而是主要设计目标。

重点考虑：

- iOS / Mobile Reading View；
- 手机单手操作；
- 不依赖右键菜单；
- 不需要打开复杂侧边栏；
- 尽量减少点击次数；
- 不遮挡正文；
- 不干扰正常文字选择和滚动；
- 在很长的 Markdown 文档中仍然保持流畅。

Desktop 同样需要正常支持，但 UI 和交互设计应优先考虑 Mobile。

## 5. UI 原则

UI 要求：

**简洁、现代、美观、克制。**

不要把它设计成一个复杂的 Bookmark 管理器。

第一阶段更接近：

> 阅读过程中的轻量导航工具。

移动端可以考虑一个小型悬浮控件，例如：

```
             ●
           ↑  ↩
```

或者一个主按钮，根据当前状态动态改变行为。

例如正常状态：

```
↑
```

点击后跳到顶部并保存当前位置。

跳转以后：

```
↩
```

点击即可返回。

更多功能可以通过：

- 长按；
- 展开小型菜单；
- Obsidian command；

访问，例如：

```
↩ 返回
↑ 顶部
← 后退
→ 前进
📍 设置返回点
```

具体视觉形式可以在开发过程中设计，但应尽量避免占据大量屏幕空间。

## 6. 一个重要原则：不要修改笔记正文

插件的导航功能不得为了保存位置而修改 Markdown 文件。

例如不要插入：

```
<!-- bookmark -->
```

也不要自动添加：

```
^block-id
```

或者修改 frontmatter。

导航状态、临时位置、历史记录和未来可能增加的书签，都应由插件自己的数据管理。

这样可以避免：

- 产生无意义的同步变化；
- Git diff 污染；
- 修改时间变化；
- 与其他插件冲突；
- 对原始 Markdown 内容产生副作用。

## 7. 位置恢复可靠性

不要单纯依赖：

```
scrollTop
```

或者固定：

```
第 500 行
```

因为笔记内容修改后位置可能发生变化。

位置模型应为未来扩展预留能力，例如组合：

- editor position；
- 行号；
- 当前 Heading / section；
- 附近文本 context；
- scroll ratio；
- 其他稳定定位信息。

第一版本不必一次实现非常复杂的定位算法，但架构上不要把位置简单定义成一个滚动像素值。

## 8. 后续可能扩展

第一版本稳定以后，可以考虑：

- 一篇笔记多个临时位置；
- 命名书签；
- 每篇笔记自动记住上次阅读位置；
- 最近访问位置；
- 当前笔记快速位置列表；
- Heading 快速跳转；
- 与其他插件之间提供简单 API；
- 从其他插件跳转到某处时，自动保存跳转前的位置。

这些不是第一版本必须完成的内容，应优先保证核心导航体验简单可靠。

## 9. 第一版本的核心目标

第一版本不要追求功能数量。

重点是把以下流程做到足够好：

> **我正在手机上阅读一篇很长的 Obsidian 笔记 → 临时离开当前位置 → 查看其他部分 → 一两次操作即可准确回来。**

如果这个体验足够自然、稳定，而且不干扰 Obsidian 本身的阅读和选择操作，那么第一版本就是成功的。
