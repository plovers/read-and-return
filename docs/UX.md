# 交互

## 核心流程

在长笔记中阅读 → 点击 ↑ → 保存可见位置并到顶部 → 点击 ↩ → 回到原处。返回成功后返回点被消耗，按钮恢复为 ↑。若想去其他章节，先在 ⋯ 菜单设置返回点，之后自由滚动或使用 Obsidian 的章节导航，再点击 ↩。

低频的“跳转到底部”放在 ⋯ 菜单中，也可通过命令面板执行，不增加常驻按钮。跳转时记住当前位置，主按钮变为 ↩；返回后恢复 ↑。已在底部（含无需滚动的短笔记）时保留原返回点和历史。

每篇笔记仅保留一个临时点。显式顶部/底部操作在未到达对应边界时会替换旧点；已经到顶部时再次执行不会破坏原点。后退/前进不会消耗独立返回点；需取消返回点时使用“清除本篇导航”。

## 移动端

默认显示主按钮和 ⋯ 菜单按钮，触摸区域均为 44 × 44 CSS 像素。使用主题颜色、安全区偏移、可调左右位置和底部间距。没有持续动画，不需要右键或长按，也没有覆盖整页的透明事件层。小控件仍会覆盖角落少量正文，可调整位置或关闭，再通过命令/移动工具栏访问操作。

菜单包括顶部、跳转到底部、返回、设置返回点、后退、前进和清除本篇记录。不可用操作使用宿主菜单的禁用态置灰；没有返回点和历史时也禁用清除。菜单保留稳定顺序，不根据主按钮状态隐藏条目，因为主按钮为 ↑ 时仍可能存在可清除的历史。可在 Obsidian 自身的移动工具栏配置中添加插件命令。

从 v0.1.1 起，移动端在控件底边下至少保留 96px，再叠加系统安全区，为底部悬浮导航栏留出空间。此规则同时适用于左右侧、阅读及编辑视图，已有 24px 等设置无需重置。移动端设置滑块显示有效底距（96–160px）；桌面继续使用原底距。预留空间不会随着导航栏隐藏而收缩，避免按钮上下跳动。这不是任意弹出菜单的碰撞检测；较高自定义工具栏可通过增加底距或切换左右侧调整。

菜单每项只保留一个原生图标，不在标题中重复箭头。命令、菜单、按钮提示、通知及设置页跟随 Obsidian 界面语言：仅简体中文使用现有中文文案，繁体中文及其余语言统一回退英文。更改宿主语言后重新加载插件可更新已注册的命令名称。

## 桌面和键盘

默认使用 ribbon 导航菜单和命令面板；悬浮按钮默认关闭。用户可自行绑定快捷键。按钮提供名称、图标、可见键盘焦点和菜单属性；没有预设快捷键冲突。键盘用户可直接执行相应命令。

## 提示和边界

设置点、清除、无可用记录和近似恢复使用短提示。正文变化导致上下文丢失时，不伪装成精确返回。非 Markdown 视图不显示悬浮控件，导航命令不可用。

历史仅代表插件导航检查点，不是 Obsidian 的文件访问历史。滚动本身不生成几十个历史项。不同笔记和同一笔记多窗格的行为参见数据模型。

真实移动端验收需检查软键盘、单手触摸、文字选择、底部栏、安全区、字体缩放和横竖屏。v0.1 自动化不等同于这些验收完成。

## 2026-10-17 设计评审取舍

当前实现的设计取舍：

- 采纳菜单去重与单语言展示；采用公开 getLanguage()，不依赖 moment.locale() 或 localStorage 内部字段。
- 返回/后退/前进已有禁用态，补齐无记录时清除的禁用态。不按 ↑ 状态隐藏清除，因为返回点与历史是独立状态。
- 正文遮挡问题成立。现阶段保留左右侧、底距和关闭控件的设置；尚未彻底消除角落遮挡。不采用滚动时 opacity 0.25 加 pointer-events:none：半透明仍遮挡文字，停止滚动后一秒内的导航点击可能穿透到正文链接。边缘拖拽可作为后续候选，需处理文字选择、触摸取消、键盘、旋转、安全区及位置持久化，不能仅增加 Y 百分比。
- 返回后的短暂视觉提示有价值，列为后续候选：应分别使用阅读/编辑模式适配，处理尚未渲染的目标、近似恢复及减少动态效果偏好，避免高亮错误段落。目前不添加未经宿主验证的正文 DOM 查询或动画。
- 不直接把定位基准改为视口 25%–30%：这是阅读偏好而非通用常量，且改变记录基准必须同步实现恢复偏移及跨模式映射。当前保留视口顶部源码坐标，顶部遮挡需要宿主实测后针对适配层处理。
- 返回成功后已经立即恢复 ↑；再次点击即可重新到顶部，也可通过后退回到刚才离开的确切位置。无需再等待向下滚动一屏。长按设置返回点暂不添加，避免与移动端选择/上下文菜单竞争，现有更多菜单和命令保持可发现性。
- 同文件链接跳转自动记历史有价值，但属后续扩展。不能用短时间滚动超过 2.5 屏可靠识别链接：快速滑动、图片加载和插件自身跳转都可能触发误判。将来应识别明确的链接导航意图，处理脚注、跨文件、取消跳转和编辑模式，再提交历史；不自动覆盖用户显式设置的返回点。
- Reading View 的延迟渲染风险值得保留，但不能把所有版本/模式的渲染细节当作公开 API 保证。当前已使用 Markdown 子视图 getScroll()/applyScroll() 和源码文本上下文，不依赖 DOM 节点序号或仅 scrollTop，也不需要额外依赖 data-line。跨模式已有模拟测试；真实超长笔记、异步内容和 iOS 精度仍需宿主验收。
