# 架构

## 组成

`src/main.ts` 是 Obsidian 插件入口，注册命令、ribbon 菜单、悬浮控件、设置页和文件生命周期事件。导航操作先读取当前 MarkdownView 的可见位置，成功执行滚动后才提交历史和返回点变化。失败时提示并保留原有返回点。

`src/adapter.ts` 是宿主适配层。Reading View 和编辑器都使用公开 `MarkdownSubView.getScroll()` / `applyScroll()` 接口，不直接调用 CodeMirror 内部实现。编辑模式包括 Live Preview、Source Mode 和移动端编辑器。保存的是视口位置而非可能位于屏幕之外的输入光标；恢复不移动光标、不调用 focus，也不改动文本选择。

跳转到底部通过 `applyScroll()` 定位到源码结束边界，再将可用滚动容器对齐到当前最大滚动距离，覆盖末行换行显示的情况。边界判断仅使用已布局的实际滚动区域（1px 容差）；容器缺失或高度为零时退回源码结束坐标，不把外层容器的零滚动范围当作已到底。异步内容加载后的高度变化仍需宿主验收。

`src/position.ts` 是纯位置模型和文本恢复算法，接受 Markdown 文本和源码行坐标（含小数）。上下文片段有长度限制，识别 ATX 标题并跳过围栏代码。操作时才扫描文本，没有滚动监听器或持续全篇索引。

`src/i18n.ts` 通过公开 `getLanguage()` 读取 Obsidian 界面语言（SDK 标注自 1.8.7 提供），仅简体中文使用现有中文文案，繁体中文及其余语言统一回退英文。所有 UI 文案使用同一映射，不读取 localStorage 或日期库语言。命令名称在加载插件时注册；更改宿主语言后重新加载插件可更新名称。

`src/session.ts` 管理单笔记返回点、前进/后退栈以及按路径索引的 LRU 会话集合。不依赖 Obsidian，可独立测试。

## 模式边界与回退

Reading View 从公开 `previewMode.containerEl` 定位 `.markdown-preview-view`：若容器自身匹配则直接使用，否则查询其内部的正文滚动区域，不使用不滚动的外层包装容器。编辑器读取视图内 `.cm-scroller`。这些 DOM 选择器用于边界判断、底部对齐和最后一级视觉比例恢复，主要定位仍通过 Markdown 子视图接口完成。找不到滚动区域时依靠源码坐标定位；这些 DOM 结构并非稳定 API，宿主布局变化后需要重新验证。

源码行坐标跨视图复用，使在 Reading View 设置的点可以在编辑模式中恢复。Obsidian 负责渲染和滚动，不通过定时器反复强制滚动，因此异步图片/嵌入加载可能让视觉位置变化。此版本不保证折叠段落内或大型单块内容的逐像素精度。

接口依据：[Obsidian 官方 API 类型定义](https://github.com/obsidianmd/obsidian-api/blob/master/obsidian.d.ts)。编译时使用锁文件中的 SDK；最低版本声明及真实平台效果仍需宿主验收。

## UI 生命周期

悬浮控件只附着到当前活动 Markdown 视图容器，绝对定位，不进入正文渲染树。控件之外不拦截滚动和触摸事件，不需要右键或长按。

通过 `Platform.isMobile` 给控件增加 `is-mobile` 类。移动端 CSS 使用 `max(用户底距, 96px) + safe-area-inset-bottom` 预留底部导航栏空间，桌面保持原规则。不提高层级覆盖宿主菜单，不增加 DOM 观察器或滚动测量。该固定预留量来自参考截图的遮挡场景，不保证避让任意高度的弹出层。

活动视图、打开文件、布局变化和文件重命名/删除会刷新控件。旧控件及其局部监听器随 DOM 移除而释放；全局事件通过 `registerEvent` 由 Obsidian 清理。卸载时移除控件和宿主样式类、清空会话。延迟布局就绪回调检查卸载状态。

## 性能与安全边界

每次显式导航时间复杂度约 O(笔记行数)，存储复杂度为有界会话数 × 有界历史项数。没有 scroll 事件订阅、DOM observer、定时持久化或网络请求。笔记文本只从当前视图读取，没有 Vault 写入、Editor 修改或正文 DOM 标记操作。

生产构建只将插件代码打包，`obsidian` 作为宿主提供的外部模块。release 不包含 Node.js 运行时依赖，适用于移动端加载。
